# CSS Basics

HTML gives your page *content*. **CSS** (Cascading Style Sheets) gives it
a *look*: colours, fonts, spacing, sizes.

The same HTML can look completely different depending on the CSS attached to it. 
The point is to seperate the styling information from the content and structure.

## How CSS attaches to HTML

The most common way — and the one we will use throughout the course — is a
separate `.css` file linked from the `<head>`:

```html
<link rel="stylesheet" href="styles.css" />
```

You can also put CSS directly in a `<style>` tag inside the page, or as an
`style="..."` attribute on a single element, but keeping styles in their
own file is what you'll see in real projects.

## The shape of a CSS rule

Every CSS rule has three parts:

```css
h1 {
  color: purple;
}
```

- **`h1`** — the *selector*. It picks which elements this rule applies to.
- **`color`** — the *property*. What are we changing?
- **`purple`** — the *value*. What are we changing it to?

The property/value pair sits inside `{ ... }` and ends with a **semicolon**.
A rule can set as many properties as you like:

```css
h1 {
  color: purple;
  font-size: 32px;
  margin-bottom: 12px;
}
```

## Selectors

Three selectors will cover most of what you need at first:

### By tag name

Targets every element of that type.

```css
p {
  line-height: 1.5;
}
```

### By class

Add a `class` attribute in the HTML, then select it with a leading dot.
Multiple elements can share the same class.

```css
<p class="intro">Welcome!</p>
```

```css
.intro {
  font-weight: bold;
}
```

### By id

An `id` is meant to be unique to *one* element. Select it with a leading `#`.

```css
<p id="callout">Read this bit.</p>
```

```css
#callout {
  background: yellow;
}
```

Prefer classes over ids for styling — you'll almost always end up wanting
the same look on more than one element.

## Common properties

A small handful of properties will get you a surprisingly long way:

- `color` — text colour.
- `background` (or `background-color`) — background colour.
- `font-family` — which font to use (e.g. `system-ui, sans-serif`).
- `font-size` — how big the text is (e.g. `16px`, `1.2rem`).
- `font-weight` — `normal`, `bold`, or a number like `600`.
- `text-align` — `left`, `center`, `right`.
- `padding` — space *inside* an element, between its content and its edge.
- `margin` — space *outside* an element, between it and its neighbours.
- `border` — a line around the element, e.g. `1px solid black`.

## Colours

You can write colours in several ways:

- Named colours: `red`, `steelblue`, `rebeccapurple`.
- Hex codes: `#ff0000` (red), `#6633cc` (purple).
- `rgb(...)` and `rgba(...)` for red/green/blue and optional transparency.

Named colours are handy for quick experiments; hex codes are what you'll
see most often in real designs.

Check out this [Color Picker](https://htmlcolorcodes.com/color-picker/) to generate hex codes for colors.

## The "cascading" part

The **C** in CSS stands for *cascading*: when more than one rule could
apply to the same element, the browser has rules for deciding which wins.
The short version:

1. More *specific* selectors win (an id beats a class beats a tag).
2. If two rules are equally specific, the one written *later* wins.

That means if a style isn't taking effect, it's usually because another, more specific rule is
overriding it.
