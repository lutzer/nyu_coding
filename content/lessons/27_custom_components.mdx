# Your Own Components

So far every page we've built lives inside one component — `App` —
and that component returns a mix of built-in HTML tags like `<div>`,
`<h1>`, and `<button>`. That's fine for a few lines, but it becomes
unreadable fast.

The real power of React is that **you can define your own tags**.
If you want a `<Card>`, you just write one — and from then on you
can drop `<Card />` into your JSX the same way you'd drop in an
`<img />`.

## Defining a component

A component is just a function that returns JSX — you've been
writing one all along (`App`). Here's a second one, defined in the
same file:

```jsx
function Card() {
  return (
    <div className="card">
      <img src="https://picsum.photos/200" alt="" />
      <p>A random picture.</p>
    </div>
  );
}
```

Two small things to notice:

- The name starts with a **capital letter** (`Card`, not `card`).
  That capital is how React tells your tags apart from built-in
  HTML ones — lowercase names are treated as plain HTML.
- There's **no `export default`** this time. `Card` only needs to
  be visible inside this file; `App` is still the one component
  that leaves the file.

## Nesting a component inside `App`

Once a component is defined, you use it in JSX just like a built-in
tag — your capitalised name, followed by a self-closing slash:

```jsx
export default function App() {
  return (
    <div>
      <h1>My Gallery</h1>
      <Card />
      <Card />
      <Card />
    </div>
  );
}
```

Three cards appear on the page. The real win: when you want to
change what a card looks like, you edit `Card` in one place and
every `<Card />` on the page updates.

## A quick detour: objects

Before we make the card configurable, there's one JavaScript shape
you haven't met yet: the **object**. Back in Lesson 23 we promised
we'd come back to it, and props are the moment it matters.

An object is a bundle of **named values**, written with curly
braces:

```js
const person = { name: "Ada", age: 29 };
```

You read a single value out of it with a **dot**:

```js
person.name   // "Ada"
person.age    // 29
```

That's the whole idea. Keep it in mind for the next section —
props arrive as an object, and you'll read them with a dot in
exactly the same way.

## Making components configurable with props

Three *identical* cards aren't very useful. Usually you want each
one to show a different picture and caption. That's what **props**
are for.

Props are inputs you pass to a component — they look exactly like
HTML attributes:

```jsx
<Card src="https://picsum.photos/200" caption="A random picture" />
```

Inside the component, those inputs arrive as the function's single
parameter, conventionally called `props`. It's an **object** — the
same shape you just met — and you read individual props with a
dot, like `props.src`:

```jsx
function Card(props) {
  return (
    <div className="card">
      <img src={props.src} alt="" />
      <p>{props.caption}</p>
    </div>
  );
}
```

The curly braces inside JSX (`{props.src}`, `{props.caption}`) let
you drop a JavaScript value into the output. Anything between `{ }`
is evaluated as code — the result is what ends up on the page.

Now every `<Card />` can be different.

## Rendering a list with `.map()`

Hard-coding three cards is fine. Hard-coding fifty is not. And
usually the data isn't fixed — it comes from a file or from state.
We need a way to produce **one `<Card />` per item in a list**.

JavaScript stores lists in an **array**. Here's an array of three
items, each one an object with a `src` and a `caption`:

```js
const pictures = [
  { src: "https://picsum.photos/seed/one/200",   caption: "One"   },
  { src: "https://picsum.photos/seed/two/200",   caption: "Two"   },
  { src: "https://picsum.photos/seed/three/200", caption: "Three" },
];
```

Arrays have a built-in method called **`.map()`** that walks through
every item and gives back a new array of transformed values. In
React, we use it to turn an array of data into an array of JSX
elements:

```jsx
{pictures.map((picture) => (
  <Card key={picture.caption} src={picture.src} caption={picture.caption} />
))}
```

Read that line as:

> *for each `picture` in `pictures`, hand back a `<Card>` with its
> `src` and `caption`.*

A few things worth unpacking:

- `(picture) => ( ... )` is an **arrow function** — a short way to
  write a function. You met the same shape when we wired `onClick`
  (e.g. `onClick={() => setCount(count + 1)}`). Here it takes one
  input (`picture`) and returns one `<Card>`.
- The whole `pictures.map(...)` expression is wrapped in `{ }`
  because it sits inside JSX — remember, braces mean *"treat what's
  inside as JavaScript"*.
- Each `<Card>` gets a **`key`** prop. React uses `key` to tell
  items apart when the list changes (an item is added, removed, or
  reordered). The value just has to be unique **within the list** —
  often an `id` field or, as here, something that's naturally
  unique like the caption. `key` is a React-only prop; your
  component never sees it in `props`.
