# Interactivity

So far every page we've built just *shows* something. In this lesson
we make the page **react to the user** — a click changes what you
see on screen.

Two new ideas do all the work:

1. **Event handlers** — functions that run when the user does
   something (clicks, types, hovers).
2. **State** — a value that React remembers *between* renders and
   that, when changed, causes the component to render again.

## Reacting to a click

Any JSX tag can take an `onClick` attribute whose value is a
function. React will call that function whenever the element is
clicked.

<SandpackSnippet folder="interactivity/click" size="large" template="react" activeFile="/App.js" />

```jsx
export default function App() {
  function handleClick() {
    alert("You clicked the button!");
  }

  return <button onClick={handleClick}>Click me</button>;
}
```

The App component registers the handleClick function as a handler for the onClick event of the button component. The handeClick function opens a simple popup.

## Why we need state

Try this in your head: you want a counter that goes up by one every
time you click. The obvious try is:

```jsx
export default function App() {
  let count = 0;
  return (
    <button onClick={() => count = count + 1}>
      Clicked {count} times
    </button>
  );
}
```

It doesn't work. The variable `count` *does* change — but React has
no way of knowing it changed, so it never re-renders the component.
The button on screen keeps showing `0`.

What we need is a value that:

1. **Survives** across renders (a normal variable gets reset every
   time the function runs).
2. **Tells React** when it changes, so the component can render
   again with the new value.

That's exactly what `useState` gives us.

## `useState`

`useState` is a function from the React library. Like `createRoot`
in the last lesson, it's a **named** import:

```js
import { useState } from "react";
```

Inside your component, call it with an initial value:

```jsx
const [count, setCount] = useState(0);
```

That one line gives you two things:

- `count` — the current value (starts at `0` the first time).
- `setCount` — a function to change it. Calling `setCount(newValue)`
  tells React "store this new value *and* re-render the component".

The square-brackets syntax (`const [a, b] = ...`) is called
**array destructuring** — it just unpacks the two things `useState`
hands back into two named variables.

Here is the counter done properly:

<SandpackSnippet folder="interactivity/counter" size="large" template="react" activeFile="/App.js" />

```jsx
import { useState } from "react";

export default function App() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Clicked {count} times</p>
      <button onClick={() => setCount(count + 1)}>Click me</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}
```

Click the button a few times — the number on screen updates. Every
`setCount` call causes React to run the `App` function again, and
this time `useState(0)` hands back the stored value instead of the
initial `0`.

## The render loop

That back-and-forth between your component and React is called the
**render loop**:

```text
     ┌────────────────────────────┐
     │ 1. React calls App()       │
     │    → returns JSX           │
     └─────────────┬──────────────┘
                   │
                   ▼
     ┌────────────────────────────┐
     │ 2. React paints the DOM    │
     │    (what you see on screen)│
     └─────────────┬──────────────┘
                   │
                   ▼
     ┌────────────────────────────┐
     │ 3. User clicks the button  │
     │    → setCount(count + 1)   │
     └─────────────┬──────────────┘
                   │
                   ▼
     ┌────────────────────────────┐
     │ 4. React stores the new    │
     │    value and loops back    │
     │    to step 1               │
     └────────────────────────────┘
```

One trip around the loop is called a **render**. On each render the
`App` function runs again from top to bottom, `useState` hands back
the latest stored value, and React compares the new JSX with what's
already on the page and updates only the parts that changed.

So the mental model is: your component is a *recipe* that React
re-runs whenever state changes. You never update the screen directly
— you update state, and React takes care of the rest.

A few rules that will save you headaches later:

- Always update state through the setter (`setCount(...)`), never by
  assigning to the variable directly.
- `useState` must be called at the **top** of your component, not
  inside an `if` or a loop. (React relies on the call order to match
  values to components.)
- You can call `useState` as many times as you need — one per piece
  of state.

## Exercise

The component below already has the logic for hiding and showing an
image:

```jsx
{visible && <img src="https://picsum.photos/300" alt="random" />}
```

That line uses a common JSX trick for *conditional rendering*. The
`&&` operator (read it as "and") looks at the value on its left:

- If `visible` is **`true`**, the whole expression becomes the
  `<img>` on the right, and React renders it.
- If `visible` is **`false`**, the expression short-circuits to
  `false`, and React renders nothing in that spot.

So the picture appears exactly when `visible` is `true`.

What's missing is the state. Your job:

1. Add a piece of state called `visible` with an initial value of
   `true` using `useState`.
2. Wire the button's `onClick` so it flips `visible` to its opposite
   value: `setVisible(!visible)`.

Click the button — the image should appear and disappear.
