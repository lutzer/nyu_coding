# React Introduction

In Chapter 1 you wrote plain HTML and CSS. The browser read your
`index.html` top to bottom and painted exactly what was there — nothing
on the page could change after it loaded.

From here on we want pages that can *change*: buttons that react to
clicks, a gallery that filters when you pick a tag, data loaded from a
file. That's what **JavaScript** is for, and **React** is a library
that makes building that kind of interactive page much easier.

## What React actually is

React is a JavaScript library for building user interfaces out of
small, reusable pieces called **components**. A component is just a
function that returns a chunk of UI.

Instead of writing one long `index.html`, you describe your page as a
tree of components — a `<Gallery>` containing many `<Card>`s, each one
containing an `<img>` and a `<Caption>`. React takes that tree and
turns it into real HTML in the browser for you.

Three ideas worth keeping in mind as we go:

- **Components** — reusable building blocks, written as JavaScript
  functions.
- **JSX** — a syntax that lets you write HTML-looking tags *inside*
  JavaScript. It's not actually HTML; it's JavaScript that produces
  elements.
- **Rendering** — React takes your components and *renders* them into
  the real DOM (the live HTML tree in the browser).

## The file structure of a React app

Up to now every snippet had a single `index.html`. A React app has a
few more files, each with a clear job:

- **`public/index.html`** — a nearly-empty HTML page. It only contains
  an empty `<div id="root"></div>` where React will mount everything.
  You rarely touch this file.
- **`index.js`** — the entry point. It tells React to render your
  top-level component into that `root` div.
- **`App.js`** — your top-level component. This is where you spend
  most of your time.
- **`styles.css`** — a regular CSS file, exactly the same CSS you
  already know.
