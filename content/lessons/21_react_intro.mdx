# React Introduction

In Chapter 1 you wrote plain HTML and CSS. The browser read your
`index.html` top to bottom and painted exactly what was there —
nothing on the page could change after it loaded.

From here on we want pages that can *change*: buttons that react to
clicks, a gallery that filters when you pick a tag, data loaded from
a file. That's what **JavaScript** is for, and **React** is a tool
that makes building interactive pages much easier.

## What React actually is

React is a JavaScript library for building user interfaces out of
small, reusable pieces called **components**. A component is a named
chunk of UI that you can drop into your page the same way you'd drop
in an `<img>` or a `<div>`.

Instead of writing one long `index.html`, you describe your page as
a tree of components — a `<Gallery>` containing many `<Card>`s, each
one containing an `<img>` and a `<Caption>`. React takes that tree
and turns it into real HTML in the browser for you.

Three words worth keeping in mind as we go:

- **Component** — a reusable building block of your page.
- **JSX** — a way to write HTML-looking tags *inside* a JavaScript
  file. It's not actually HTML; the browser never sees JSX directly —
  React turns it into real HTML elements.
- **Rendering** — React takes your components and *renders* them
  into the real DOM (the live HTML tree in the browser).

## What's coming next

React is written in JavaScript, so before we can really read the
file above, we need a tiny bit of JavaScript vocabulary — just
enough to recognise the pieces. The next lesson is a short detour
into pure JavaScript: **variables** and **functions**. Once those
two ideas click, the rest of React is mostly new names for things
