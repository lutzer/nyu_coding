# Reading a JavaScript File

In Chapter 1 you wrote **HTML** (what is on the page) and **CSS**
(what it looks like). Both are descriptions — the browser reads them
and paints exactly what they say.

**JavaScript** is different. A JavaScript file is a list of
*instructions* the browser follows, one after another. It's a
programming language, and it's what lets a page do things instead of
just sit there.

In a React app, you write JavaScript in files that end in `.js`. The
most important one is `App.js`, the file you'll spend most of your
time in. Open the sandbox below and keep `App.js` visible — we'll
walk through it piece by piece.

Here's the whole file:

```jsx
export default function App() {
  return (
    <div>
      <h1>Hello from React!</h1>
      <p>This paragraph is rendered by a React component.</p>
    </div>
  );
}
```

That's only a few lines, but almost every word is new. Let's take
them one at a time.

## Functions

A **function** is a named, reusable block of instructions. You can
think of it as a little machine: you give it a name, you write what
it does between curly braces `{ ... }`, and later something can
*call* it to run those instructions.

The simplest possible function looks like this:

```js
function sayHello() {
  // instructions go here
}
```

Three parts:

- The keyword **`function`** — tells JavaScript "a function is coming".
- A **name** (`sayHello`) — how you refer to it later.
- A pair of **curly braces** `{ ... }` — the *body* of the function.
  Everything between the braces is what the function does when it
  runs.

The empty parentheses `()` after the name are for *inputs*. We're
not using any yet, but they always have to be there.

Look at `App.js` again:

```jsx
function App() {
  ...
}
```

That's a function named `App`. In React, **every component is a
function** — and a component's job is to describe a piece of the
page. By convention, component functions start with a **capital
letter** (`App`, not `app`).

## `return` — handing a value back

A function can hand something back to whoever called it. The keyword
for that is **`return`**. Whatever comes after `return` is the
function's *output*.

```js
function two() {
  return 2;
}
```

A React component's job is to return the chunk of UI it represents.
Look at the `App` function — the `return` hands back a `<div>` with
some tags inside:

```jsx
return (
  <div>
    <h1>Hello from React!</h1>
    <p>This paragraph is rendered by a React component.</p>
  </div>
);
```

The parentheses `( ... )` after `return` are just a wrapper so we
can spread the returned value over several lines. They are not doing
anything clever.

## JSX — HTML inside JavaScript

Those `<div>`, `<h1>` and `<p>` tags look exactly like HTML from
Chapter 1, but they're sitting inside a JavaScript file. That mix
has a name: **JSX**.

JSX lets you write HTML-looking tags right inside your JavaScript.
It's not real HTML — React translates it into real HTML elements
when it renders your component.

A few small rules that will trip you up at first:

- A component must return **one** element. If you want several tags
  side by side, wrap them in a parent `<div>` (or an empty wrapper
  `<>...</>`).
- Every tag must be **closed**. Self-closing tags end with ` />`:
  `<img src="..." />`, `<br />`, `<hr />`.
- The HTML attribute `class` becomes **`className`** in JSX, because
  `class` is a reserved word in JavaScript.
- JSX comments go inside braces: `{/* like this */}`.

## Variables

Besides functions, JavaScript lets you give names to *values*. A
named value is called a **variable** — think of it as a labeled box
holding something.

You create a variable with the keyword **`const`** (short for
*constant*):

```js
const greeting = "Hello";
const count = 3;
```

Read `const greeting = "Hello";` as *"let the name `greeting` stand
for the text `"Hello"`"*. From that line on, writing `greeting` in
the file means `"Hello"`.

`const` means the name won't be reassigned. There is another keyword
`let` for values that *will* change later — we'll meet it when we
need it.

We don't need any variables inside `App` yet, but we'll start using
them in the next lesson.

## Exports — sharing a function with other files

Look at the very first line of `App.js`:

```js
export default function App() { ... }
```

The two extra words — **`export default`** — mean *"make this
function available to other files in the project"*. Without them,
`App` would exist only inside `App.js` and no one else could use it.

Each file in a JavaScript project is its own little world: variables
and functions you declare in one file are **not** visible in another
unless you deliberately share them. That's what `export` is for.

A file can `export default` **one** main thing — usually its most
important function or component. That's why `App.js` uses it: the
whole file exists to produce one component.

## Imports — pulling things in from other files

The partner to `export` is **`import`**. Now switch to `index.js` in
the sandbox:

```js
import { createRoot } from "react-dom/client";
import App from "./App";
import "./styles.css";

const root = createRoot(document.getElementById("root"));
root.render(<App />);
```

The top three lines are all imports — each pulls something in from
somewhere else so this file can use it. There are three flavours
visible here.

### Default imports

```js
import App from "./App";
```

This picks up the one thing that `App.js` marked as `export default`
and calls it `App` here. The path `"./App"` means *"a file next to
this one named `App`"*. The leading `./` is important — it says
"look in my own project". You don't need to write `.js` at the end;
the bundler figures that out.

### Named imports

```js
import { createRoot } from "react-dom/client";
```

A file can also export several things *by name*. To pull in a named
export, you put the exact same name inside curly braces.

Notice this path has **no** `./` in front. That tells JavaScript
"this isn't one of my own files — look in the installed packages
(`node_modules`)". That's how we pull in React itself.

### Side-effect imports

```js
import "./styles.css";
```

Sometimes you import a file not to get a value out of it, just to
*include* it. For CSS, this tells the bundler "attach this
stylesheet to the page". No variable comes out; the rules in the
file just start applying.

## Reading `index.js` top to bottom

With all of that in mind, `index.js` is now a short recipe:

```js
import { createRoot } from "react-dom/client";
import App from "./App";
import "./styles.css";

const root = createRoot(document.getElementById("root"));
root.render(<App />);
```

1. Pull `createRoot` from the React library (a *named* import).
2. Pull our own `App` function from the file next door (a *default*
   import).
3. Attach the stylesheet (a *side-effect* import).
4. Store the result of `createRoot(...)` in a variable called
   `root`. `createRoot` finds the empty `<div id="root">` inside
   `public/index.html` and sets it up as the place React will draw
   into.
5. Call `root.render(<App />)` to actually render the `App`
   component into that spot.

You will almost never change this file — but it is what glues your
component to the page.
