# JavaScript Basics

You just saw a React component. It had a name, some JSX inside,
and the word `return` saying what to hand back. All of that is
written in **JavaScript** — the language React is written in.

Unlike HTML and CSS, which *describe* a page, JavaScript is a
list of *instructions* the browser follows one after another.
Before we go further, let's slow down and learn the two JavaScript
ideas that make a component tick:

1. **Variables** — giving names to values.
2. **Functions** — giving names to a chunk of instructions.

No React in this lesson, no HTML tags — just these two ideas on
their own. The snippets below each come with a little terminal on
the right: whenever your script calls `print(...)`, a new line
shows up there. **Edit the code, see the terminal update.**

## Variables — a labeled box for a value

A **variable** is a name you attach to a value, so you can refer to
it later. Think of it as a labeled box: on the label you write a
name, inside the box you put a value.

You create a variable with the keyword **`const`** (short for
*constant*). Have a look at the editor — then try the suggestion
in the comment:

<SandpackSnippet folder="javascript_basics/variables" template="static" activeFile="/script.js" />

Read `const greeting = "Hello";` as:

> *"Let the name `greeting` stand for the text `"Hello"`."*

From that line on, writing `greeting` anywhere in the file means
`"Hello"` — which is why `print(greeting)` ends up printing
`Hello` in the terminal. The second line does the same with a
number.

- **Strings** go in quotes (`"Ada"` or `'Ada'`). Numbers don't.
- **Booleans** are only ever `true` or `false` — no quotes.
- **Arrays** use square brackets `[ ... ]` and hold a list of values.

There's one more kind — **objects** — that we'll meet later, when
we start passing data between components.

### `const` vs `let`

`const` means the name stays attached to the same value — you
won't reassign it. If you need a variable whose value *will*
change later, you use **`let`** instead.

The snippet below has both. Follow the comment and uncomment the

to change the value later.

## Functions — a named chunk of instructions

A **function** is a reusable block of instructions with a name.
You can think of it as a little machine: it has a name, a body
(the instructions), and you *call* it to make it run.

The simplest possible function has no inputs. Look at `sayHello`
in the editor:

<SandpackSnippet folder="javascript_basics/functions" template="static" activeFile="/script.js" />

Four parts to spot in the code:

- The keyword **`function`** — tells JavaScript "a function is coming".
- A **name** (`sayHello`) — how you refer to it later.
- A pair of **parentheses** `()` — for inputs (empty here, we'll
  get to that in a moment).
- A pair of **curly braces** `{ ... }` — the *body* of the function.
  Everything between the braces is what the function runs when it's
  called.

Writing the function alone doesn't do anything — it just *defines*
the machine. The three `sayHello();` lines below the definition
are what actually make it run. Delete one of them and watch a
line disappear from the terminal.

### Parameters and `return`

Most functions aren't useful without inputs. **Parameters** are
names for the values a function expects when it's called. They go
inside the parentheses after the function name.

And usually you want the function to *compute* a value and hand
it back so you can use it elsewhere — that's what the keyword
**`return`** is for.

The snippet below shows both ideas at once: `greet` takes a
`person` and returns a sentence; `add` takes two numbers and
returns their sum.

<SandpackSnippet folder="javascript_basics/functions_return" template="static" activeFile="/script.js" />

Read `greet("Ada")` step by step:

1. The function runs with `person = "Ada"`.
2. Inside, `return "Hello, " + person + "!"` hands back the
   string `"Hello, Ada!"`.
3. `const message = ...` stores that returned value in a new
   variable called `message`.

Inside a function body, a parameter behaves like a normal
variable — except its value comes from whoever called the
function. Call `greet("Ada")` and `person` is `"Ada"`; call
`greet("Linus")` and `person` is `"Linus"`.

A function can return any kind of value — a number, a string, a
boolean, an array… or, as we'll see soon, even a chunk of UI.

## Back to the component

Flip back to `App.js` from the last lesson in your head:

```jsx
function App() {
  return (
    <div> ... </div>
  );
}
```

Now you can read it with the right vocabulary:

- `App` is a **function**. The `function` keyword and the name
  tell you so.
- It takes no **parameters** — the parentheses `()` are empty.
- It **returns** a value — in this case the `<div>`.

That's the whole trick: **every React component is a function
whose return value is a piece of the page**. In the next lesson
we'll meet one more JavaScript idea — **arrays** — because React
builds pages out of lists.

## Exercise

Time to put the ideas together. The sandbox starts with three
variables: a `productName`, a `price`, and a `quantity`.

Your job:

1. **Write a function from scratch.** Add a function
   `total(price, quantity)` that **returns** the price times the
   quantity. Don't print inside the function — just return the
   number. The first print at the bottom should then show
   `total: 300`.
2. **Combine strings, numbers, and a function call.** Make a
   variable called `summary` that holds the sentence like
   `Headphones x3 = $300`. You'll need to glue a few pieces
   together with `+`: `productName`, the literal `" x"`, the
   `quantity`, the literal `" = $"`, and the result of calling
   `total(price, quantity)`. The second print will then show it.

Things to watch out for:

- `return` hands a value back — a function that `print`s but doesn't
  `return` will give you `undefined` when you try to use its result.
- JavaScript's `+` joins strings but adds numbers; when a string is
  on either side, numbers get turned into strings. That's exactly
  what you want for `summary`.
- If something goes wrong, the terminal now shows the error. Read
  it top to bottom — the message usually points at the problem.
